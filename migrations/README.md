# Миграции

Текущая полная схема и запланированные дополнения показаны в
[ERD](../docs/database-erd.md).

SQL-миграции выполняются через [golang-migrate](https://github.com/golang-migrate/migrate).

```sh
make migrate-up       # применить все новые миграции
make migrate-version  # текущая версия
make migrate-down     # откатить одну миграцию (удаляет её таблицы и данные)
```

При запуске полного стека Compose применяет миграции перед стартом приложения.
Новые версии добавляются парами `NNNNNN_name.up.sql` / `NNNNNN_name.down.sql`.
Уже применённые миграции не редактируются.

Начальная миграция повторяет `poydem-database-schema.md`: nullable-поля,
значения по умолчанию и девять рекомендуемых индексов сохранены. Внешние ключи
используют стандартное `NO ACTION`, без каскадного удаления. Временные поля
заполняет приложение; триггеров и автоматического обновления `updated_at` нет.

Для перечисленных в схеме статусов и типов добавлены `CHECK`. Перечни
`users.role` и `users.status` в схеме пока не определены. Полиморфную ссылку
`reports.target_id` и согласованность участия с членством в компании нужно
дополнительно проверять в бизнес-логике.

Миграция `000002` добавляет refresh-сессии. Текущий и предыдущий SHA-256 hash
позволяют выполнить атомарную ротацию с коротким окном повтора после потери ответа;
исходные refresh-токены в БД не хранятся.

Миграция `000003` усиливает инварианты событий: обязательные внешние ключи, статус
и timestamps, проверка `ends_at > starts_at`, а также индексы для публичного каталога
и событий пользователя. Перед применением к базе с существующими неполными событиями
такие строки нужно исправить вручную: обязательные ссылки невозможно восстановить
автоматически без продуктового решения.

Миграция `000004` добавляет soft delete компаний, обязательные значения и
timestamps компаний, участников и записей участия. Она ограничивает размер
компании значениями 2–100, роли — `owner/member`, согласует тип участия с
наличием `company_id` и составным внешним ключом гарантирует принадлежность
компании тому же событию. Также добавлены индексы списка компаний события и
списка компаний пользователя.

Миграция `000005` усиливает заявки: обязательные ссылки, статус и время создания,
поле системной причины завершения и частичный уникальный индекс, разрешающий
только одну pending-заявку пользователя в конкретную компанию. Отклонённые и
отменённые заявки остаются историей и не мешают повторной подаче.

Миграция `000006` добавляет внутренний ключ объекта аватара. Публичный URL остаётся
в `avatar_url`, а ключ используется для безопасного удаления старого файла из
S3-совместимого хранилища без разбора URL.

Миграция `000007` добавляет координаты мероприятия, источник точки и причину
модерации. Ограничения БД проверяют парность и диапазоны координат, а частичный
индекс ускоряет выборку активных точек в видимой области карты.

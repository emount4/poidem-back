# Архитектура

Проект устроен как модульный монолит. Код группируется по бизнес-возможностям,
а не по общим техническим слоям.

```text
cmd/api                 точка входа
internal/app            сборка зависимостей и жизненный цикл
internal/api            общий HTTP-слой и версии API
internal/catalog        модуль справочников
internal/platform       инфраструктура без бизнес-логики
migrations              миграции PostgreSQL
```

Каждый бизнес-модуль хранит рядом свои модели, сервисы, интерфейсы хранилищ,
реализацию PostgreSQL и HTTP-адаптеры. Например, `internal/catalog` не зависит
от Gin или конкретного драйвера базы данных; эти зависимости находятся в
`catalog/httpv1` и `catalog/postgres`.

Новые возможности добавляются отдельными модулями: `account`, `events`,
`companies`, `reports`. Связь между модулями проходит через небольшие интерфейсы
на стороне вызывающего модуля. Сборка конкретных реализаций выполняется только
в `internal/app`.

Общие HTTP middleware и маршрутизация версий находятся в `internal/api`.
Конфигурация, логирование, PostgreSQL и Request ID находятся в
`internal/platform`.
